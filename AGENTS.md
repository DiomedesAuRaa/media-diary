# Public apps repository guidance

This is the public, read-only diary viewer and the public Nokia-oriented tools/games collection. Keep the career Portfolio site separate at its established URL. Do not add LAN writer/API modules, credentials, runtime data, backups or operations files here.

The six files in `data/` are public diary data. The renderer exports only its explicit `PUBLIC_FIELDS`; do not broaden this allowlist without review. Feed selections in `tools/sub.yaml`, `tools/scripts/reddit-config.json`, `tools/scripts/news-config.json` and `tools/sports-config.json`, plus generated feed digests, are public preferences/content. Weather location overrides, compact-mode settings and game progress/scores stay local to the browser. Both project sites use the same browser origin, so preserve existing localStorage keys.

`python3 scripts/build_public.py --output _site` is the complete Pages build. Keep its output allowlists curated; never copy the repository recursively. Feed refresh scripts belong under `tools/scripts/`, tests under `tools/tests/`, and generated feed JSON at the corresponding paths in `tools/`. Validate feed output before publication and retain last-good data on failures.

Tools use shared assets in `tools/assets/`. Preserve semantic controls, visible amber focus, navy/teal surfaces, touch-sized controls, normal scrolling and ordinary browser navigation. On screens at or below 280px, compact controls may use the existing smaller target size. Keep game key capture scoped to active gameplay and do not capture keys from text fields or navigation.

Treat feed text and URLs as untrusted. Render text safely and allow only intended HTTP(S) destinations. Keep the World English Bible label accurate. Weather defaults to Atlanta; city overrides remain device-local and geolocation stays optional.

Dynamic services use ToolUI.fetch with a 12-second header/body deadline and existing retry/error states. Keep provider requests bounded and preserve weather/Bible request-version guards. News uses build-time static category/pagination routes with a durable validated digest. Pages and feed workflows share a publication queue and every deploy builds the full current-main artifact. Never deploy a tools-only artifact over the diary.

All sports pages use the shared `tools/assets/sports-data.js` adapter for live reads, device cache and validated published fallback. Browser requests use the verified `site.web.api.espn.com` host for scoreboards, standings and rankings; server-side snapshots keep canonical `site.api` keys. Never substitute the server host in browser requests. Request only selected/favorite leagues initially, bound global concurrency/deadlines, cancel unstarted work when selection changes, and preserve actual retrieval/last-good timestamps. Query individual calendar days; the tested range query returns400. NCAA FBS uses groups80/limit100 and men's college basketball groups50/limit365 from probes; don't assume a highlimit or page/offset gives full coverage. Keep stable provider IDs and every competition/session, including scheduled F1 sessions without drivers. `coverage.complete` means requested dates succeeded, not independently guaranteed provider completeness. Keep no-key collection, URL/config allowlists, projected fields and serialized full-site publishing. These unofficial routes have no SLA; retain fallback and verify CORS/browser behavior after changes. Legacy live-scores.js is not a second live publisher/client for the new sports pages.
Today and schedule consume the same shared adapter and published fallback. Today must inspect enabled scoreboard endpoints only, not mark standings entries as missing game data. Retain stale headlines and show partial source failures. Schedule queries an explicit multi-day window of returned scoreboards; disclose queried/failed dates and local kickoff times without claiming guaranteed complete provider coverage. Shared ToolUI.favoriteTeam matches complete aliases against provider team names/abbreviations, never substrings that confuse Michigan with Michigan State. Broadcast projections contain only bounded public names/market labels.

Product reviews must exercise complete tasks, not just page layout and API success: selection, paging, empty results, errors/retry and retained state; games also need start, pause where supported, loss/win and restart. Check 240px keypad navigation, 390px touch layout and laptop keyboard focus. Browser emulation does not establish compatibility with physical Nokia hardware or Safari.

Physical Nokia photos exposed collapsed 2048 tiles and excessive header/control height despite passing Chrome viewport checks. Keep explicit board width/height and square tile fallbacks that work without CSS min()/clamp()/aspect-ratio; modern layout declarations must not erase those fallbacks. Test short usable viewports as well as width, since browser chrome takes part of the 320px screen. At keypad widths, compact controls must work without requiring a saved preference or toggle. Preserve browser scrolling and game storage when fixing layout. Hardware rendering still requires user verification after publication.

Remove a feed only with evidence of a broken endpoint or invalid feed. Repeated access-denied responses can reflect provider blocking; preserve validated last-good snapshots and label them honestly. When removing sources, update configuration and the real saved digest together so strict validators still pass. Reloading a static digest does not force a provider refresh. After rebuilding paginated content, restore focus to a live control rather than a removed DOM node. Score coverage must include all returned events before favorite selection; make display limits explicit.

Diary browsing defaults to all media. Completion-year filters must preserve search/sort/category/history context and reset for For later. Public controls stay disabled until all six datasets load; retain honest native no-JavaScript navigation. At 240px search occupies its own row and the first entry should fit in a short usable viewport. Keep private/public diary CSS synchronized.

Public details are generated only from PUBLIC_FIELDS-projected rows at details/{type}-{mode}-{hash-occurrence}.html. Hash routes identify current snapshot rows, not durable work identities. Keep nested asset links and native browse fallback valid. details-index.json is an explicit derived path-only artifact aligned with six dataset arrays; validate route syntax/lengths before enhanced rendering. On load failure retain native entries and support Retry. Public details must never gain mutation/LAN routes. Summary counts all media for the selected completion year independently of search/category and labels distinct titles approximate.

Note is intentionally public by user choice and belongs in PUBLIC_FIELDS and exported JSON/details. Do not include it in compact browse rows; preserve escaped multiline plain text. LegacyCSVheaders may omit only Note, not other requiredfields. Public route hashes exclude Note so adding/editing a note retains existing session bookmarks; private editkeys remain separate. Related sessions get View links only, marked currententry and identified by date/rating/creator/release.
